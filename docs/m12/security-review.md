# M12 internal security review

Scope: ColorAdapt 0.1.0, production builds (`dist/chrome-mv3`, `dist/firefox-mv2`), source at the M12 candidate.
Method: a static pass over `src/` for every sink and surface named below, then runtime evidence in the real browsers
where a static answer is not enough. This is an internal review by the author of M12, not an independent audit. Every
"evidence" cell names something that can be re-run.

## Result

| Severity | Open at the freeze                                                                  |
| -------- | ----------------------------------------------------------------------------------- |
| Critical | 0                                                                                   |
| High     | 0                                                                                   |
| Medium   | 0                                                                                   |
| Low      | 0 open. Two found and fixed during M12 (F1, F2); one hardening gain delivered (F3). |

## Findings found and fixed in M12

| #   | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Class                                   | Fix                                                                                                                     | Evidence                                                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | **Prototype key from page-controlled text.** Per-site profiles are keyed by hostname, and `http://__proto__/` and `http://constructor/` are valid URLs. A stored `__proto__` key replaced the prototype of the overrides object (the profile vanished and its fields became inherited properties), and a host named `constructor` read an inherited function as its "profile", so `enabled` came back `undefined` and adaptation was silently off there. | Prototype pollution (local, not global) | `schema.ts` defines the key as an own property; `resolveEffectiveSettings` reads own properties only (`Object.hasOwn`). | `tests/infrastructure/storage/hostname-keys.test.ts` (failed before, passes)                                                                                               |
| F2  | **Unvalidated settings write.** `UPDATE_SETTINGS` merged any patch into the stored object without parsing it, so a context could persist out-of-range numbers, unknown enums or arbitrary extra fields (the reader sanitized them later, but the stored shape was not controlled). The merge is now parsed before it is written.                                                                                                                         | Input validation                        | `SettingsStore.update` stores `parseUserSettings({ ...current, ...patch })`.                                            | `storage-corruption.test.ts`; `state.spec.ts` "write after corruption" (both browsers); the upgrade spec's behavioral probe                                                |
| F3  | **Network surface enforced only by code.** The extension pages could technically connect anywhere if a code path ever did. The manifest now carries a Content Security Policy for extension pages: `script-src 'self'; object-src 'self'; connect-src 'self' http://127.0.0.1:* http://localhost:* http://[::1]:*`.                                                                                                                                      | Defense in depth                        | `wxt.config.ts` (`content_security_policy`), frozen in the golden, enforced by `audit-dist`.                            | `messaging.spec.ts` "P14/P17" (both browsers): remote, LAN, WebSocket, inline and remote script all blocked; loopback and self allowed; `ai-provider.spec.ts` still passes |

Other defects found by M12 (availability and robustness, not security): D1 orphaned content script kept its stylesheet
after an extension reload (Chrome); D2 the audit page rendered a blank page for `?tabId=99999999999999999999`; D4 text
contrast of the popup's link-style buttons in dark mode was 3.62:1. See the report's _Defects_.

third-party model runtime the user chooses to run on their loopback (ColorAdapt treats its output as untrusted data).
